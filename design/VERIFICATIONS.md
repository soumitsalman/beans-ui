# Beans UI Verifications

These are the current acceptance cases for the mobile-first UI. Verification records distinguish fixture checks from live API behavior.

## Google Trends home defaults

- Country selection: weighted Accept-Language order, q=0 exclusions, lowercase regions, script subtags, invalid entries, wildcards, missing/language-only preferences and numeric regions. Country must come from an explicit two-letter locale region; Fly headers/server location do not select trends.
- Country caching: Google query geo must match uppercase country, cache keys must isolate countries, and failures/empty results must not cache. Check country → US → unfiltered fallback and only one US attempt when US is selected. Verify trend_country survives SSR hydration, More and Retry alongside original tags/from/cursor. Refresh/Clear reselect defaults. Home HTML must be private/no-store while data caches still work.
- Live RSS verification on 2026-10-23: IN, BR and US each returned HTTP 200 with ten keyword items. Production fixtures use separate IN keywords and an empty BR feed to verify country-specific backend tags and US fallback without q/score_threshold. Keep the checkout's repeated-key request serialization unchanged.

- Run `node scripts/verify-query-encoding.mjs` to confirm the proxy passes array query values unchanged to Nuxt `$fetch`, and that `/search` writes repeated `tags` and `sources` keys. The production discovery fixture captures the resulting request URL. A direct request to the running API verifies that exact URL independently.

- Default home uses UTC today minus three days as `from`, five stories, repeated English `languages` keys and US Google trend keywords as repeated backend `tags` keys; omit default `q` and `score_threshold`. Category feeds retain seven days. User topic/saved tags bypass Google; Clear and empty Find restore trend defaults without writing them to the input, URL or cookie.
- Parse keyword titles only, including single-item feeds, CDATA and XML entities; preserve complete phrases, spelling and punctuation (trim outer whitespace only), remove duplicates/empty values and cap at 30 tags. Related article titles must not become tags.
- Successful non-empty keyword lists remain cached for six hours (`maxAge: 21600`, `swr: false`). Expiry refreshes synchronously. Google timeout, failure, malformed XML and empty lists are not cached; home falls back to unfiltered news.
- SSR snapshots include effective default tags. Hydration makes no duplicate initial request. More and Retry retain the original tags, date and cursor across cache expiry; an empty fallback tag list stays unfiltered during continuation. A failed refresh preserves visible stories and retries its own criteria rather than an older cursor.
- Run `node scripts/verify-google-trends.mjs` for parsing, actual installed Nitro cache expiry with isolated storage/controlled time, hydration and client-state cases; `node scripts/verify-stories.mjs` for server filter/fallback/window cases; production discovery fixtures intercept Google fetches and assert repeated default `tags` keys. These are fixture checks, not live Google or Beans behavior.

## API requests

| Surface | Route and request | Acceptance |
| --- | --- | --- |
| Home and categories | Beans `/preview/stories?limit=5` | Make one request initially and one with the returned `cursor` per More action. Return renderable stories without waiting for favicon or confidence enrichment. Send repeated English `languages` keys, `content_type=news`, and a three-day home/seven-day category `from` date fixed across pagination. Home omits `categories`; category pages send their category IDs as repeated keys. Preserve non-empty `q`, normalized repeated `tags` keys, and `score_threshold` only with `q`. Default home adds the Google keyword `tags` described above and no generated `q`. Omit `sort` and `exclude_ids`. |
| Story detail | Beans `/preview/stories/{story_id}` | Fetch the story with the existing English `languages` and `content_type=news`. Use `last_published_at` for the date and `article_count` for the article label; accept `artcles_count` only as an input fallback. |
| Story publisher icons | Beans `/preview/stories/{story_id}/articles?limit=20` | After a home/category batch renders, request its story IDs in one deferred presentation action. Make exactly one article request per story, without following its cursor. Select at most three distinct non-null, non-empty `source.favicon_url` values; fewer than three is valid. Story cards and the story snapshot render only those URLs and remove an avatar whose image fails, without a newspaper icon, initial, legacy favicon, or Google substitute. Retain all returned article IDs for confidence, even when icons are missing or repeated. An enrichment failure leaves the cards usable. |
| Coverage | Beans `/preview/stories/{story_id}/articles?limit=100` | Drain cursor pages until complete, without `languages` or `content_type`. Deduplicate articles; repeated cursors stop safely, and a failed page does not masquerade as complete coverage. |
| Related | Beans `/preview/stories/{story_id}/articles?limit=5` | Send repeated English `languages` keys and `content_type=news`. Keep a cursor independent of Coverage and request the next page only on More. |
| Source metadata and feed | Beans `/sources/{source_id}` and `/articles/latest?sources={source_id}&sort=recent&limit=5` | Start with repeated English `languages` keys and `content_type=news`. Only when the API `data` array is empty, retry without `content_type`; if still empty, retry without `languages`. Preserve source ID, sort, limit and cursor in all attempts; stop at the first non-empty result and keep only matching source IDs. Errors use Retry without relaxing filters. |
| Search | Beans `/articles/search?limit=5` and `/search` | Preserve `q`, normalized repeated `tags` keys, repeated English `languages` keys, `content_type=news`, and `score_threshold` only with non-empty `q`. Map the Sources input to repeated `domains` keys, never publisher-ID `sources`. The `/search` route writes repeated `tags` and `sources` keys and still reads a comma-separated URL. Preserve cursor and filters on More and Retry. |
| Source/search article-card icons | Beans `/preview/stories/{story_id}/articles?limit=20` | Enrich a story-backed article once without cursor continuation. Show up to three distinct other publishers with non-null, non-empty `source.favicon_url` values, excluding its primary source; fewer than three is valid. Render only those URLs and remove an avatar whose image fails, without a newspaper icon, initial, legacy favicon, or Google substitute. |
| Sitemap | Static public routes | List home, About, and category URLs. Do not request Beans articles, and do not include story or source URLs. `/feed.xml` is absent. |
| Confidence | Espresso `/preview/confidence` | Send repeated `ids` keys for Beans article IDs, never story IDs. For a story, batch at most 100 distinct IDs from its 20-article publisher response, stop querying that story after any non-null result, and choose the highest conflicting value. Display only `high`; missing or failed scores show no badge. Source/search article confidence uses article IDs. |

Array-valued Beans filters and Espresso `ids` are repeated query keys passed through Nuxt `$fetch`. Internal Beans and Espresso endpoints use `/preview`; public source and search routes keep their paths. API credentials remain server-side. Cached public feed requests expire after 30 seconds, discovery searches after 12 hours, and failures are not cached.

API retrieval has a 90-second timeout. The server action deadline is 95 seconds and the browser request deadline is 100 seconds. A timeout aborts outstanding uncached work and yields a retryable failure; no automatic retry occurs.

## Feed and page behavior

| Case | Expected result |
| --- | --- |
| Initial render and hydration | Home and category HTML contain five StoryCards as soon as `/preview/stories` returns, before favicon/confidence calls finish. Hydration restores the story cursor and date window without repeating the initial collection request; one deferred enrichment action updates those cards. Source and search feeds continue to use ArticleCard. |
| More and refresh | A null or repeated cursor hides More. A short or duplicate-only page triggers no automatic fill request; an empty page with a new cursor permits another manual More. During More, visible cards stay in place and the button is the only loading indicator; no separate spinner appears below the grid. Refresh resets the cursor and retains a compact updating indicator when no More control is available. A failed More preserves visible cards and retries the same cursor. |
| Home discovery | The home URL's `q` and the `beans_home_discovery` cookie synchronize the topic and saved tags. A route topic overrides the saved topic while preserving saved tags. Clear or an empty Find removes `q`, clears saved criteria, and restores the three-day five-story feed with Google trend tags (unfiltered when Google fails). `score_threshold` uses `NUXT_PUBLIC_DEFAULT_SCORE_THRESHOLD` (default `0.6`) only when `q` is non-empty. |
| StoryCard | Omit the primary source favicon and site name. Clicking the card, title or image opens `/stories/{story.id}`; source-avatar and share controls retain their own actions. The category starts at the left; published date, high-confidence badge and trend indicator align at the right in that order. The date comes from `last_published_at`; the article label uses `article_count`. |
| Story page | `/stories/{story.id}` uses the same category/date/confidence/trend header alignment. Coverage and Related have independent loading, error and cursor state. A failed Coverage page retains earlier loaded items; Related hides More when its cursor ends. `/articles/{id}` is no longer a detail route. |
| Source page | Source metadata precedes a five-item `/articles/latest` feed. The publisher URL displays without a scheme and gains `https://` when the API supplies no scheme. The source favicon overlaps the profile card; the feed has a divider without a Latest news heading. |
| Search and article cards | Search keeps topic, tags and source domains in its URL. ArticleCard retains its source line, ideology display, publisher icons, outbound image link and article-specific sharing. A story-backed card links to `/stories/{story_id}`; a story-less card links to its publisher URL. Only high confidence is visible. |
| Sharing and discovery | Coverage shares a Beans story URL; original mode uses the publisher URL with Beans attribution while preserving unrelated query values and fragments. Metadata and structured data use story URLs where a story ID exists. The sitemap lists stable public routes. `/archive` and `/feed.xml` remain absent. |
| Responsive layout | Home, category, source and search feeds have one column below `md` and two at `md` and above. Initial story and article states use matching card-shaped skeletons: story metadata/title/media/footer, and article source/category/signals/title/media/footer. Related stays one column below `lg`. Cards, controls, coverage timeline and sharing fit a 320px viewport without horizontal overflow. |
| Navigation and errors | Fast route changes and Back/Forward cannot let an older response replace the current feed. Confirmed missing resources yield 404/410; temporary failures yield 503 with Retry. A 429 displays a shared Retry-After countdown and disables data actions until it expires. Static About, methodology and empty Search navigation spend no data-action quota. |

Story summaries appear once, clamp to two lines on cards and three on the detail snapshot, and precede region/entity tags. Image failure moves summary and tags below the title. Positive trend counts render without fabricated zero values or a numeric trend score. Missing confidence and ideology create no placeholder. Publisher and coverage avatar groups retain their bounded counts and fallback icons.
