# Beans UI Verifications

These are the current acceptance cases for the mobile-first UI. Verification records distinguish fixture checks from live API behavior.

## API requests

| Surface | Route and request | Acceptance |
| --- | --- | --- |
| Home and categories | Beans `/preview/stories?limit=5` | Make one request initially and one with the returned `cursor` per More action. Return renderable stories without waiting for favicon or confidence enrichment. Send repeated English `languages`, `content_type=news`, and a seven-day `from` date fixed across pagination. Home omits `categories`; category pages send their category IDs. Preserve non-empty `q`, normalized `tags`, and `score_threshold` only with `q`. Omit `sort` and `exclude_ids`. |
| Story detail | Beans `/preview/stories/{story_id}` | Fetch the story with the existing English `languages` and `content_type=news`. Use `last_published_at` for the date and `article_count` for the article label; accept `artcles_count` only as an input fallback. |
| Story publisher icons | Beans `/preview/stories/{story_id}/articles?limit=20` | After a home/category batch renders, request its story IDs in one deferred presentation action. Make exactly one article request per story, without following its cursor. Select at most three distinct non-null, non-empty `source.favicon_url` values; fewer than three is valid. Retain all returned article IDs for confidence, even when icons are missing or repeated. An enrichment failure leaves the cards usable. |
| Coverage | Beans `/preview/stories/{story_id}/articles?limit=100` | Drain cursor pages until complete, without `languages` or `content_type`. Deduplicate articles; repeated cursors stop safely, and a failed page does not masquerade as complete coverage. |
| Related | Beans `/preview/stories/{story_id}/articles?limit=5` | Send repeated English `languages` and `content_type=news`. Keep a cursor independent of Coverage and request the next page only on More. |
| Source metadata and feed | Beans `/sources/{source_id}` and `/articles/latest?sources={source_id}&sort=recent&limit=5` | Start with repeated English `languages` and `content_type=news`. Only when the API `data` array is empty, retry without `content_type`; if still empty, retry without `languages`. Preserve source ID, sort, limit and cursor in all attempts; stop at the first non-empty result and keep only matching source IDs. Errors use Retry without relaxing filters. |
| Search | Beans `/articles/search?limit=5` | Preserve `q`, normalized repeated `tags`, repeated English `languages`, `content_type=news`, and `score_threshold` only with non-empty `q`. Map the Sources input to repeated `domains`, never publisher-ID `sources`. Preserve cursor and filters on More and Retry. |
| Source/search article-card icons | Beans `/preview/stories/{story_id}/articles?limit=20` | Enrich a story-backed article once without cursor continuation. Show up to three distinct other publishers with non-null, non-empty `source.favicon_url` values, excluding its primary source; fewer than three is valid. |
| Sitemap and RSS | Beans `/preview/articles/unique` | Fetch recent English news with `sort=recent`, `limit=100`, and a seven-day `from` date. Generate story URLs from story IDs and avoid duplicate story entries. |
| Confidence | Espresso `/preview/confidence?ids={article_ids}` | Send comma-separated Beans article IDs, never story IDs. For a story, batch at most 100 distinct IDs from its 20-article publisher response, stop querying that story after any non-null result, and choose the highest conflicting value. Display only `high`; missing or failed scores show no badge. Source/search article confidence uses article IDs. |

Array-valued Beans filters use repeated query keys. Internal Beans and Espresso endpoints use `/preview`; public source and search routes keep their paths. API credentials remain server-side. Cached public feed requests expire after 30 seconds, discovery searches after 12 hours, and failures are not cached.

API retrieval has a 90-second timeout. The server action deadline is 95 seconds and the browser request deadline is 100 seconds. A timeout aborts outstanding uncached work and yields a retryable failure; no automatic retry occurs.

## Feed and page behavior

| Case | Expected result |
| --- | --- |
| Initial render and hydration | Home and category HTML contain five StoryCards as soon as `/preview/stories` returns, before favicon/confidence calls finish. Hydration restores the story cursor and date window without repeating the initial collection request; one deferred enrichment action updates those cards. Source and search feeds continue to use ArticleCard. |
| More and refresh | A null or repeated cursor hides More. A short or duplicate-only page triggers no automatic fill request; an empty page with a new cursor permits another manual More. Refresh resets the cursor. A failed More preserves visible cards and retries the same cursor. |
| Home discovery | The home URL's `q` and the `beans_home_discovery` cookie synchronize the topic and saved tags. A route topic overrides the saved topic while preserving saved tags. Clear or an empty Find removes `q`, clears saved criteria, and reloads the unfiltered five-story feed. `score_threshold` uses `NUXT_PUBLIC_DEFAULT_SCORE_THRESHOLD` (default `0.6`) only when `q` is non-empty. |
| StoryCard | Omit the primary source favicon and site name. Clicking the card, title or image opens `/stories/{story.id}`; source-avatar and share controls retain their own actions. The category starts at the left; published date, high-confidence badge and trend indicator align at the right in that order. The date comes from `last_published_at`; the article label uses `article_count`. |
| Story page | `/stories/{story.id}` uses the same category/date/confidence/trend header alignment. Coverage and Related have independent loading, error and cursor state. A failed Coverage page retains earlier loaded items; Related hides More when its cursor ends. `/articles/{id}` is no longer a detail route. |
| Source page | Source metadata precedes a five-item `/articles/latest` feed. The publisher URL displays without a scheme and gains `https://` when the API supplies no scheme. The source favicon overlaps the profile card; the feed has a divider without a Latest news heading. |
| Search and article cards | Search keeps topic, tags and source domains in its URL. ArticleCard retains its source line, ideology display, publisher icons, outbound image link and article-specific sharing. A story-backed card links to `/stories/{story_id}`; a story-less card links to its publisher URL. Only high confidence is visible. |
| Sharing and discovery | Coverage shares a Beans story URL; original mode uses the publisher URL with Beans attribution while preserving unrelated query values and fragments. Sitemap, RSS, metadata and structured data use story URLs where a story ID exists. `/archive` remains absent. |
| Responsive layout | Home, category, source and search feeds have one column below `md` and two at `md` and above. Related stays one column below `lg`. Cards, controls, coverage timeline and sharing fit a 320px viewport without horizontal overflow. |
| Navigation and errors | Fast route changes and Back/Forward cannot let an older response replace the current feed. Confirmed missing resources yield 404/410; temporary failures yield 503 with Retry. A 429 displays a shared Retry-After countdown and disables data actions until it expires. Static About, methodology and empty Search navigation spend no data-action quota. |

Story summaries appear once, clamp to two lines on cards and three on the detail snapshot, and precede region/entity tags. Image failure moves summary and tags below the title. Positive trend counts render without fabricated zero values or a numeric trend score. Missing confidence and ideology create no placeholder. Publisher and coverage avatar groups retain their bounded counts and fallback icons.

## Verification record — 2026-10-12

- Focused story-service fixtures confirm that the feed makes only its collection request before returning five renderable stories. A separate enrichment action fetches the same limit-20 story-article pages and article-ID confidence batches; detail-page enrichment remains synchronous. Focused lint, Nuxt typecheck and production build pass. Production HTTP fixtures confirm home SSR emits five cards without making publisher or confidence calls, and the protected deferred action returns icons and confidence afterward. In the local fixture browser, home and category each showed five enriched cards, More appended five, and the browser request log placed `/api/actions/story_enrichment` after the home document request. Client paint timing was not measured.
- Story-service fixtures pass for field mapping, five-story initial and continuation requests, retained filters and date window, omitted `sort`/`exclude_ids`, cursor safety, one limit-20 favicon request, distinct icons, confidence batches of at most 100 article IDs, highest conflicting confidence, early stop, unfiltered 245-article Coverage, filtered five-item Related, source fallback, and preview publisher enrichment. Fixture upstream calls reject a `/private` prefix. These service checks use injected responses, not a live API.
- Production HTTP fixtures pass for initial home/category SSR, More, query and cache behavior, source rendering, metadata and action boundaries. The live local Beans story collection returned five stories and a cursor; More displayed ten. Live story detail displayed complete Coverage for a 276-article story and Related pagination from five to ten. The live Mail Online source page displayed five article cards with no load error.
- Live local Beans `/preview/stories/{id}/articles?limit=50` returned HTTP 200. Beans `/preview/articles/unique` and the configured Espresso `/preview/confidence` returned HTTP 404 at the last check; live behavior for those routes remains unverified. No stale-prefix fallback is used.
- Browser checks on story cards and detail confirmed category alignment at the left, date before confidence/trend at the right, and no horizontal overflow in the inspected story viewport. Earlier fixture checks covered 320px feed, sharing, source profile, image fallback and coverage-orbit layouts.
- The timing check asserts 90-second upstream, 95-second server and 100-second browser limits, plus deadline cancellation and Retry-After parsing. Focused lint, Nuxt typecheck and production build passed after the timeout change. The full 90-second stalled-upstream HTTP check has not been rerun; an earlier 60-second stall check passed and confirmed connection abort.

Historical route and feed experiments have been removed from the active acceptance cases. `design/WORKLOG.md` retains the change history; current data contracts are in `design/DATASOURCES.md`.
